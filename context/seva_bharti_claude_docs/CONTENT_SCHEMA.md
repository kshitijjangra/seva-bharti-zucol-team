# Content and Asset Rules

## Source of truth
Use only user-provided text, documents, photographs, and explicitly
approved information.

## Pillars
1. Shiksha
2. Swavalamban
3. Samajik
4. Swasthya

These labels are derived from the supplied audio transcription.
Confirm their official spelling and exact public-facing names before launch.

## Suggested local structure
Keep content in typed local TypeScript or JSON files, for example:

- `src/content/site.ts`
- `src/content/pillars.ts`
- `src/content/events.ts`

Use only fields supported by supplied material.

## Missing fields
Missing information must remain absent or use an editorial placeholder,
for example:

`[CONTENT REQUIRED: official pillar description]`

Do not put editorial placeholders into the public production website
as though they are final content.

## Photographs
- Use only supplied images.
- Preserve original files.
- Do not generate replacement photographs.
- Do not claim a photograph depicts a particular event or person unless
  the user has supplied that information.
- Use descriptive filenames where possible.
- Ask for captions or alt-text context when it is not evident.

## Success stories
Include only stories explicitly supplied and approved by the user.
Never create sample people, outcomes, quotes, or impact figures.

## Events
Only include events for which information or photographs have been supplied.
Do not invent event dates, names, locations, descriptions, or captions.

## Contact
Use only verified contact details supplied by the user.

## Editorial checklist
Before publishing, identify every placeholder and every piece of content
that needs user verification.
